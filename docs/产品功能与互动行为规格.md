# 产品功能与互动行为规格

## 产品定义

本项目是**具身互动机器人台灯**，而不只是“绘本伴读台灯”。伴读是首个可交付场景；最终目标是保留 LeLamp 所代表的语音、灯光、相机、录制回放和五轴表情能力，并形成更自然的“看见—理解—反应”互动感。

参考方向：LeLamp 将五轴运动、Pi 相机、声音、可编程 LED 与录制/回放组合为表达型机器人灯；本项目借鉴其产品能力，但采用 MKS SERVO42D CAN 闭环步进和自己的安全、CAN 与动作架构。[LeLamp](https://github.com/humancomputerlab/LeLamp) [LeLamp Runtime](https://github.com/humancomputerlab/lelamp_runtime)

## 互动感的实现方法

互动感不来自“每一帧都让视觉模型算一次电机角度”。那样慢、昂贵、且会造成机械抖动。采用分层行为系统：

```text
相机 / 麦克风 / 传感器
        ↓
感知层：移动、稳定、人物存在、手、书、目标物类别与位置
        ↓
注意力层：当前最值得关注的对象是谁？置信度是否足够？
        ↓
行为层：注视、好奇、欢迎、陪读、倾听、害羞、休息、避让
        ↓
动作层：选择动作片段、设定目标姿态、平滑混合、SEQ/INT/TRJ 仲裁
        ↓
MKS CAN：每轴 FOC / 编码器闭环 / 本轴加减速
```

### 第一版人物方向：离散左右注意力，而非连续追脸

第一版不需要让相机的每一帧人脸坐标直接驱动五轴连续追踪。人物方向只分为 `LEFT`、`CENTER`、`RIGHT` 三个注意力扇区；其中 `LEFT` 和 `RIGHT` 是主要大方向。每个扇区对应一套已经校验过的安全注视姿态，例如 `look_left`、`look_right`、`look_center`。

```text
有人说话 / 唤醒词 / 人体稳定出现
        ↓
相机估计粗略方位（左、中、右）
        ↓
已有可信方位？→ 转到该预设姿态
没有可信方位？→ 先缓慢 look_right → 等待视觉确认 → look_left
        ↓
仍找不到？→ 回到 center / listening，不反复扫描
```

- 扫描仅在用户主动唤醒、刚检测到有人但方向不确定时进行；每轮最多右、左各一次，并有冷却时间。
- 相机一旦在某一扇区连续确认有人，就锁定该方位一小段时间，避免左右跳变。
- 用户可以用自然语言纠正：**“我在这里”**、**“我在另一边”**、**“你看错了”**、**“看左边/右边”**。这些属于本地允许意图：立即 `INT` 打断当前的柔性扫描，转向指定/相反扇区，再用视觉做一次确认。
- “另一边”在已有 `LEFT/RIGHT` 注视状态时含义明确：转到相反一侧；若当前是 `CENTER` 或未知，则回复一次简短澄清或进行一次低速右后左扫描。
- 语音纠错只是改变注意力方位，绝不绕过软限位、速度上限或安全状态。

## AI 与本地程序如何协作（已确定）

大模型**不能直接连接 CAN、GPIO 或电机**，也不能输出任意 Python 代码或电机角度。大模型只扮演“互动导演”；树莓派本地程序才是拥有安全权限的执行者。

```text
本地相机/麦克风 → 结构化事件 → 大模型（可选）→ 结构化行为建议
                                            ↓
                                     本地白名单验证
                                            ↓
                               动作库 / LED / 语音 / MKS CAN
```

每次调用大模型时，本地程序发送的是有限的上下文，例如：

```json
{
  "event": "object_stable",
  "objects": [{"label": "book", "position": "center", "confidence": 0.91}],
  "current_behavior": "idle",
  "allowed_actions": ["look_center", "look_left", "nod", "curious_tilt", "read_mode", "stay_still"],
  "safety_state": "READY"
}
```

大模型只能返回符合固定 schema 的建议，例如：

```json
{
  "speech": "我看到一本书，我们一起读吗？",
  "emotion": "curious",
  "attention_target": "book",
  "action": "read_mode",
  "led_expression": "warm_attention"
}
```

本地验证器必须拒绝以下情况：动作名称不在白名单、状态不是 `READY`、动作冷却未结束、目标不可见、命令频率过高、限位/故障/急停存在。验证通过后，`action` 才被映射为本地录制或手工设计的五轴动作片段，最后通过 `SEQ / INT / TRJ` 发送给 MKS。

本地视觉的对象不是一句“书在这里”，而是带坐标的对象记录，例如 `book-1`、`label=book`、`center=(0.25, 0.55)`、`confidence=0.91`。AI 返回 `action=look_at, target_id=book-1` 后，本地注视模块才会把这个画面坐标映射为 J1/J4/J5 的安全目标角度。AI 不需要、也不允许自己计算关节角度。

若 AI 说“这是一个球，轻轻碰一下它”，它会请求 `touch_target(ball-1)`，而不是直接写 CAN 命令。此动作只有在本地将球定位到三维可达空间、确认球是可轻触物体、路径无障碍、速度/动作幅度受限时才会批准；否则只允许 `look_at(ball-1)`、`curious_tilt` 和语音回应。第一版只能做灯头带软胶保护圈的**极低速轻触**，不能做撞击或高速“踢球”。

### 不需要为每个物体写一份提示词或动作

- **提示词：**一个稳定的系统提示词描述角色、边界、当前可用动作与输出 schema；每次仅发送最新事件。不是“给杯子一套提示词、给书一套提示词”。
- **物体：**本地检测器先给出类别和位置；云端视觉只在稳定事件上补充语义，例如“这是一个恐龙玩具”。没有必要事先录入世界上所有物体。
- **动作：**第一版建立约 20–40 个安全的基础动作片段：待机呼吸、看左/右/中、抬头、低头、点头、摇头、歪头、靠近书、回待机等。大模型选择动作 ID，本地把动作片段混合、限速并执行。新动作可由手动示教录入一次后复用。
- **情绪：**本地保存连续的情绪/精力状态，例如 `calm`、`curious`、`happy`、`listening`；大模型只能建议状态变化。本地行为机决定持续时间和强度，避免每句对话都突然换一个表情。

### 何时调用大模型

| 场景 | 是否调用大模型 | 本地动作 |
|---|---|---|
| 连续追踪手/人位置 | 否 | 本地低频注意力与平滑注视 |
| 限位、急停、CAN 故障 | 否 | 本地立即停机 |
| 用户语音指令“停止/回待机/开始示教” | 否 | 本地白名单命令 |
| 新物体稳定出现、用户提问、绘本解释 | 是，可选 | AI 提议一句话与一个动作 ID |
| 长对话 | 是，可选 | AI 生成语言和高层情绪；本地限制动作频率 |

当前 [cloud.py](../lamp_core/cloud.py) 已能向模型发送稳定图像并获得文本。下一步会把它升级为“受 schema 约束的行为建议”接口；不会让模型返回可直接执行的 CAN 帧。OpenAI Responses API 支持结构化输入/输出和工具式工作流，但实际模型调用仍必须遵守本地安全验证。[OpenAI Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)

### 互动行为例子

| 看到/听到的事件 | 行为选择 | 动作和反馈 |
|---|---|---|
| 人走近或手进入桌面区域 | `INT` 打断待机，进入关注状态 | 灯头缓慢看向目标、短暂停顿、柔和亮灯 |
| 用户挥手或呼叫 | 欢迎 | 先抬头再轻微点头；语音问候 |
| 一本书在画面中心稳定 | 陪读 | 进入看书姿态、保持安静或开始讲解 |
| 翻页/书被移走 | 注意力重置 | 停止讲解、轻微后仰、等待新目标 |
| 玩具/杯子等已支持物体出现 | 好奇 | 看向物体、轻微歪头、用一句短语回应 |
| 连续无目标 | 待机 | 小幅“呼吸”动作和低亮度灯光，定时休息 |
| 触发限位/故障/急停 | 安全 | 立即停止动作，红色状态灯/蜂鸣提示（急停不依赖软件） |

## 视觉与隐私策略

1. **本地低成本感知优先：**画面运动、静止、书页区域、手/人体存在先在 Pi 本地处理。
2. **语义识别按需触发：**只有目标稳定、置信度足够、且需要语言解释时才调用云端视觉。
3. **默认不做身份识别：**识别“有人/手/书/杯子”，不识别“这个人是谁”；不保存儿童人脸。
4. **云端必须可见且可关：**状态灯提示、监护人选择开启、只上传当前稳定帧、不永久缓存。
5. **物体类别逐步增加：**第一批只支持 `book`、`hand`、`person`、`toy`、`cup`；不把通用识别结果直接转换为高速动作。

Raspberry Pi 3B 的算力有限，因此物体识别采用“低帧率本地轻量模型 + 事件触发云端解释”的组合，而不是一直运行大型模型。若后续需要实时多物体检测，再增加 USB AI 加速器或升级 Pi，而不是牺牲运动安全。

## 距离与轻触传感器方案（已记录）

为支持“灯头看向并极低速轻触桌上球/玩具”，相机二维坐标不足以判断距离；灯头需加装与相机同向的 ToF 距离模块。

| 阶段 | 传感器 | 作用 | 连接 |
|---|---|---|---|
| 第一版 | `VL53L1X` 单点 ToF | 灯头已对准目标后，确认正前方距离是否允许接近 | Pi I²C：3.3V/GND/SDA(GPIO2)/SCL(GPIO3) |
| 互动升级版 | `VL53L5CX` 8×8 多区 ToF | 获取前方粗略位置与距离，更稳地确认球、手、玩具的可达性 | Pi I²C：3.3V/GND/SDA(GPIO2)/SCL(GPIO3) |

- ToF 与 Camera Module 3 的 CSI 接口、CAN HAT 的 SPI 接口不冲突。
- Pi 3B 的 USB 资源和算力有限，USB 深度相机不作为第一版方案。
- 触碰动作仍必须使用软胶灯头保护圈、极低速度、短行程、到达距离后立即后退；ToF 只提供距离确认，不能代替硬件急停或机械限位。
- `touch_target` 必须先经过“目标可见 → 画面定位 → ToF 距离确认 → 可达/无障碍校验 → 低速接近”的本地流程。

## 语音麦克风选型（已确定：低成本版）

第一版使用**单一 USB UAC 麦克风**（Linux 即插即用的 USB 声卡标准），安装在底座前侧或灯体固定腔体，直接接 Pi 3B 的 USB 口。麦克风不装在灯头，因此不需要穿过五个活动关节走 USB 线。人物/物体的方向完全由相机视觉决定，麦克风只负责“听见说话”。

```text
固定位置 USB 麦克风 ─ USB ─ Pi 3B
Pi Camera 3 ─ CSI ───────────┘ → 人/手/书的视觉位置 → 灯头注视
```

- 购买条件：商品必须明确写 `USB Microphone`、`UAC / USB Audio Class`、支持 Linux；不要买只能配手机 App 的蓝牙麦克风。
- 绘本模式采用**可打断播放**：讲述按自然短句播放并记录当前句；本地 VAD 检测到孩子连续说话后立即终止当前音频。问题静音结束后才发送多语言转写，回答仍使用同一音色。
- 回答结束后重新确认相机仍看到同一页；相同则用固定丹麦语过渡句 `Godt spørgsmål. Nu læser vi videre.`，从被打断句的下一句继续，不从头重复。若页面已变则不续读。
- 默认回答和故事语言保持丹麦语；“请用中文说”等明确要求只改变当前一次回答，过渡句与后续故事自动恢复丹麦语。
- 不使用“按住说话”交互按钮。普通单麦克风若要在扬声器播放时接受插话，必须在系统音频层启用声学回声消除；软件的较高插话阈值只作为第二道保护，不能替代回声消除。
- 物理急停仍必须保留，但它是安全装置，绝不作为日常交互按钮。
- 以后确实需要远场拾音、回声消除和声源方向时，再升级 USB 麦克风阵列；不是第一版前置条件。

### ESP32 是否需要

第一版**不加 ESP32**。它不能替代 Pi 上的中文语音识别，且仍要处理供电、固件、Wi-Fi/串口传输和调试。后续若灯头需要很多 LED、ToF、触摸传感器或按钮，才可增加 ESP32-S3 作为灯头传感器/灯光协处理器；它通过现有 24 V 降压供电和 CAN/UART 回传事件，不负责安全运动或语音大模型。

## 顺滑动作的规则

- 使用动作片段（如 `look_left`、`nod`、`curious_tilt`）而非每次从零写机械臂指令。
- 新动作与当前动作必须做姿态/速度过渡；目标变化小则微调，变化大则先减速再转向。
- `INT` 可打断，但永远遵守每轴速度、加速度、软限位和硬限位。
- 连续注视只以低频目标更新；MKS 内部负责单轴 FOC 与曲线加减速。
- 同一时间只保持一个“主行为”；说话、LED 和轻微头部动作可协同，但不能与大幅臂部动作相互争抢。
- 建立“动作预算”：长时间静止保持会发热，主动降低保持电流、定期回待机、限制连续大幅摆动。

## 体验验收标准

第一版互动体验达标，不以“像工业机械臂一样快”为目标，而以以下标准判断：

1. 人/书进入画面后，台灯在安全范围内以自然、低速的动作给出回应，不抖动、不反复改变主意。
2. 从待机转为注视的动作有起停缓冲；书页翻动时能及时停止讲解和追随。
3. 同一事件在置信度不足时不乱动；视觉丢失、CAN 超时、限位异常时停机。
4. 手动示教一个点头或欢迎动作后，能被保存、编辑并以低速回放。
5. 语音、LED、姿态表达在同一个行为状态下相互一致。

## 开发顺序

```text
0. 单轴 MKS CAN 安全联调
1. 五轴 CAN、回零、限位与基础表情动作
2. 手动示教、编辑、回放
3. LED、麦克风、本地语音打断
4. 本地视觉：移动/书/手/人/目标区域
5. 行为状态机与动作库：待机、欢迎、好奇、陪读、倾听
6. 可选云端语义理解与故事互动
7. 手机网页控制台与 systemd 自启动
```

任何高层 AI、物体识别或网页功能都不拥有绕过急停、限位或 CAN 故障停机的权限。
