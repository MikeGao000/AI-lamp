# 绘本伴侣灯：今日最终代码与流程

更新日期：2026-08-21

这份文档记录今天已完成、已经测试的代码基线，以及已经确定的硬件与控制流程。**Python 源文件本身是唯一代码真源**；本文通过链接索引全部源码，不复制一份可能过期的代码。

产品的完整功能范围（伴读之外的 LeLamp 式互动、语音、LED、示教与物体互动）见：[产品功能与互动行为规格](产品功能与互动行为规格.md)。

## 1. 今日确定的第一版硬件方向

```text
Raspberry Pi 3B + Pi Camera Module 3
        + 灯头 ToF（第一版 VL53L1X；互动升级版 VL53L5CX）
        + 固定位置的单一 USB UAC 麦克风（视觉决定关注方向）
        │
微雪 RS485 CAN HAT（原型可用基础版；正式版优先隔离 HAT (B)）
        │ CANH / CANL 直线主干
MKS SERVO42D CAN × 5（首选有对应手册的固件 V1.0.8）
        │
5 个直驱闭环步进关节 + 低重心灯体
```

- 不使用总线舵机。
- 不使用同步带、减速带或外露减速机构。
- 第一版使用 MKS SERVO42D **CAN**；电机板内负责 FOC、编码器闭环和本轴加减速。
- 树莓派负责“五轴应摆成什么姿态”、动作顺序、视觉、语音和示教记录。
- 硬件急停必须独立切断所有电机使能/动力，网页或 Python 停止按钮不能代替急停。
- MKS 的尾部 PCB 朝固定连杆/底座腔体收纳；电机转轴仍位于关节轴线，不使用侧置电机。

## 2. CAN 接线结论

CAN 在电气上是多节点并联，线束上采用直线主干，**不是被动 1 分 5 星形线**：

```text
Pi 3B ─ CAN HAT ─ J1 ─ J2 ─ J3 ─ J4 ─ J5
             CANH ─────────────────────── CANH
             CANL ─────────────────────── CANL
```

- 每一台 MKS 都接同一对 `CANH / CANL`，但设置不同节点 ID：J1=1、J2=2、J3=3、J4=4、J5=5。
- 总线两端各一个 120 Ω 终端：CAN HAT 端一个，J5 端一个；J1～J4 的终端跳帽关闭。
- 24 V 电源另行并联到每台 MKS，分支加保险；不能串联供电。
- 先接一台电机并完成通讯/回零/低速位置运动，再扩到五台。

## 3. 责任边界

| 层 | 谁负责 | 做什么 |
|---|---|---|
| 行为层 | 树莓派 Python | 看书、点头、动作选择、示教、云端/语音 |
| 总线层 | CAN HAT + Python | 给不同 CAN ID 发送命令、读取状态、心跳检查 |
| 单轴实时层 | 每台 MKS SERVO42D CAN | FOC、电流/位置闭环、编码器纠偏、内部加减速 |
| 物理安全 | 限位、急停、电源支路 | 不依赖树莓派地停止或失能 |

树莓派不产生 `STEP` 脉冲。它给每轴发送“目标角度、速度、加速度/动作参数”；MKS 自己执行实时 FOC 与本轴运动曲线。

## 4. 三种动作模式（必须保留）

借鉴 Dummy-Robot 的控制思想，软件已完成协议无关的命令仲裁：

| 模式 | 行为 | 示例 |
|---|---|---|
| `SEQ` | 前一段确认完成后才执行下一段 | 抬头 → 点头 → 回待机 |
| `INT` | 清空全部软动作，立即用新目标覆盖 | 书本移动、用户碰触、暂停 |
| `TRJ` | 有限缓冲的连续轨迹段 | 示教回放、自然动作 |

安全优先级：

```text
硬件急停 > 驱动器故障 / 硬限位 > 通信或状态机故障 > INT > SEQ > TRJ
```

## 6. 已实现的软件流程

```text
相机检测到书页移动
        ↓
清空静止计时，不执行阅读动作
        ↓
页面持续静止达到阈值（默认 1.5 秒）
        ↓
拍摄 JPEG
        ↓
若用户启用云端：发送图像给视觉模型；否则使用本地预置回应
        ↓
安全状态机检查：已经回零、无故障、驱动已使能
        ↓
生成五轴“看书”姿态 → 运动 → 本地语音讲述
```

当前仿真版本中，五轴 trajectory 会发送到 [virtual_hardware.py](../lamp_core/virtual_hardware.py)，不会打开串口、GPIO 或 CAN。

## 7. 手动示教流程

```text
先回零并确认软限位
        ↓
将 MKS 失能，或经单轴实测确认低保持力矩模式
        ↓
手动摆动灯臂
        ↓
以时间戳连续记录 J1~J5 的编码器角度
        ↓
保存 JSON → 平滑 → 限位校验
        ↓
默认以 35% 速度进入 TRJ 队列回放
```

示教记录格式由 `teach.py` 控制，包含：

```json
{
  "format_version": 1,
  "name": "nod",
  "joint_names": ["j1_base_yaw", "j2_shoulder"],
  "samples": [
    {"time_s": 0.0, "positions_rad": {"j1_base_yaw": 0.0, "j2_shoulder": 0.0}}
  ]
}
```

真实录制时要把 `joint_names` 替换为完整五轴名称。没有完成回零，不允许相信断电前的记录坐标。

## 9. 树莓派软件流程（电机到货前）

```bash
sudo apt install -y python3-picamera2 python3-opencv espeak-ng can-utils
cp .env.example .env
python3 app_main.py --mode pi
```

云端视觉默认关闭。只有在 `.env` 中明确设置 `ENABLE_CLOUD_VISION=true` 和 `OPENAI_API_KEY` 后才会上传稳定页面图像；儿童图像上传必须经过监护人同意。

CAN HAT 插入后，未来真实硬件验证会先确认：

```bash
ip link show can0
sudo ip link set can0 up type can bitrate <按 MKS CAN 手册填写>
candump can0
```

不要在没有确认 MKS 对应固件手册和 CAN 波特率时猜测 CAN 帧或发送电机运动命令。

## 10. 真实电机到货后的严格顺序

1. **核对货物：**每台均为 `MKS SERVO42D CAN`，同一批次、同一固件，并取得对应 CAN 手册。
2. **单台无负载：**接 24 V、CAN H/L、一个物理急停；电机固定在桌面，未装灯臂。
3. **先只读：**读取节点 ID、编码器、速度、故障、限位输入；不发送运动。
4. **回零：**低速测试一个常闭限位，确认触发即失能；设置零点和软限位。
5. **低速位置测试：**只移动几度，确认方向、到位、堵转和急停。
6. **单轴示教：**失能手动转动，录制与低速回放。
7. **逐轴增加：**一次只增加一个新关节；每次重新测试急停、限位、供电压降与温升。
8. **五轴动作：**确认 42D 实物固件的组播/同步命令后，接入 `SEQ / INT / TRJ` 真正 CAN 适配器。
9. **网页控制台：**在真实单轴 CAN 测试稳定后增加 Pi 本地网页，供手机/电脑访问；网页不能代替急停。

## 12. 明天或电机到货后的代码工作顺序

```text
1. 建立 mks_can.py：只读状态与严格帧校验
2. 建立 single_axis_demo.py：安全单轴验证
3. 将 MKS CAN 适配器接入 safety.py / smart_motion.py
4. 接入 teach.py：真实编码器示教、JSON 保存、低速回放
```

任何阶段出现未知状态、总线超时、限位异常、编码器误差或急停，都应停止进入下一阶段。
