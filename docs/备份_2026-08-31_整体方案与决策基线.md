# 绘本伴侣灯：整体方案与决策基线

更新日期：2026-08-30

本文是当前硬件、互动、模型和安全决策的单一入口。它说明目标架构与分阶段路线；真实 MKS CAN 帧、每轴负载参数和校准值仍以随货手册与单轴实测为准。

## 1. 产品目标

做一盏五轴、会看、会听、会说、会用姿态表达的互动台灯。它首先是绘本陪伴设备，随后扩展为可进行中文、英文和丹麦语交流的桌面伙伴。

互动不是让模型直接操纵机械臂，而是：模型理解人和画面；本地系统把理解转为有限、可验证的行为；电机驱动器闭环执行已批准的姿态。

## 2. 当前决策

- 主控为 **Raspberry Pi 3B**，运行 Linux、本地安全逻辑、行为编排、相机/音频接入和 CAN 主站。
- 运动为 **MKS SERVO42D CAN × 5**；每台电机自行完成 FOC、编码器闭环和本轴轨迹。Pi 不产生 STEP 脉冲。
- AI 提供商和模型**不锁定**。系统根据任务、语言、质量、延迟、价格和可用性路由到不同模型。
- 支持中文（`zh`）、英文（`en`）和丹麦语（`da`）；一场对话开始后固定其模型、声音和语言，避免中途切换造成声音或上下文突变。
- 云端模型永远没有 CAN、GPIO、关节角或任意代码权限。它只能输出文本、语音和受限的 `BehaviorProposal`。
- 第一版不需要 ESP32。若 Pi 的全双工音频/视频负载与回声消除实测不达标，才增加 ESP32-P4+C6 作为**专职媒体前端**，Pi 继续是唯一动作安全与 CAN 主控。
- VLX-Seek 1.5-10B 不部署在 Pi、Orange Pi 或 ESP 上；它是未来可选的局域网 GPU 视觉服务器。

## 3. 目标架构

```text
Pi Camera 3 / USB 麦克风 / 扬声器 / ToF / 限位
                     ↓
              Pi 3B 本地服务
  感知事件 · 语言会话管理 · 行为状态 · 动作队列 · 安全闸门
        ↓                         ↑
   模型路由器 ── HTTPS / WebSocket ── 云端模型（可替换）
        ↓
  仅文本、语音、对象语义、受限行为建议
        ↓
SafetyGate → MKS CAN 适配器 → CAN 总线 → 5 × SERVO42D
        ↓
硬件急停 / NC 限位 / 24 V 电机电源支路（独立于 Pi）
```

可选扩展：

```text
ESP32-P4+C6：相机、全双工音频、回声消除、媒体编码、Wi-Fi
        ↕ UART 或局域网受限消息
Pi 3B：对话/行为/安全/CAN 的唯一批准者
```

P4+C6 只发送媒体事件和受限意图，例如 `voice_wake`、`user_speech`、`person_left`；不得发送电机角度、原始 CAN 帧或“立即运动”命令。

## 4. 职责边界

| 层 | 组件 | 负责 | 不负责 |
|---|---|---|---|
| 硬件安全 | 急停、NC 限位、保险、使能/电源切断 | 在故障时让电机失能 | 依赖 Pi 或网络判断 |
| 单轴执行 | MKS SERVO42D | FOC、编码器闭环、内部加减速、保持 | 理解视觉或对话 |
| 本地安全 | Pi `SafetyGate` | 校准、软限位、速度/加速度、心跳、温度/故障、动作仲裁 | 生成自由动作 |
| 本地行为 | Pi 行为服务 | 事件冷却、目标选择、动作 ID、情绪连续性 | 绕过安全门 |
| 感知 | Pi 或未来 P4 | 静止、运动、粗略方位、音频流 | 直接驱动关节 |
| 模型路由 | Pi | 语言/任务/预算/降级选择 | 为模型授予硬件权限 |
| 云端/局域网模型 | 可替换提供商 | 语义、对话、视觉解释、TTS/ASR | CAN、GPIO、Shell、关节角 |

## 5. 多模型与多语言策略

模型按能力选择，而不是按品牌选择。

| 任务 | 首选原则 | 失败或超预算时 |
|---|---|---|
| `STOP`、急停、回待机、示教 | 本地固定指令/词表 | 拒绝任何云端替代 |
| 唤醒、VAD、语言初判 | 本地轻量组件优先 | 进入按键/网页控制或半双工模式 |
| 实时语音/视频聊天 | 目标语言的首字延迟、打断、语音自然度 | 降级为 ASR → 文本模型 → TTS |
| 绘本解释、复杂画面 | 图像理解准确度和儿童内容约束 | 简短本地模板，或提示稍后再试 |
| 物体在哪/指向哪个实例 | 本地检测器；未来可选 VLX-Seek GPU 服务 | 仅给出 LEFT/CENTER/RIGHT，不靠猜测移动 |
| 常规文字对话 | 质量、价格、响应时间 | 切换到同语言备用模型 |

模型路由的输入至少包含：`language`、`task`、`requires_audio`、`requires_vision`、`max_latency_ms`、`session_budget` 和 `privacy_mode`。配置中维护每个能力的首选与备用模型；密钥和供应商 URL 不写入动作或安全模块。

建议的会话规则：

1. 本地或云端 ASR 先识别 `zh` / `en` / `da`；用户可在网页中覆盖语言。
2. 新会话根据该语言选择实时模型和声音；会话内固定。
3. 每个会话与每天都设置费用上限；超过上限时降级为本地命令和短句 TTS。
4. 所有模型输出先转换为统一的 `BehaviorProposal`，再经白名单、安全门和动作冷却。

## 6. 音视频互动

### Pi 3B 第一版

- Pi Camera Module 3 采集画面；默认采用低频、事件触发图像，而不是逐帧云端推理。
- USB UAC 麦克风与扬声器承担语音；优先半双工，避免普通单麦克风的自回声。
- 云端实时模型可用于丹麦语、英文或中文对话，但模型在云端运行，Pi 只是媒体客户端和安全主机。
- 网络断开时仍可执行本地停止、故障提示、回待机和固定短句；不得因断网而继续新的追踪运动。

### 何时加入 P4+C6

只有在以下实测条件出现时才加入：需要稳定全双工、可打断对话；远场回声消除不足；需要持续低延迟视频流；或灯头增加多麦、显示和大量传感器。加入后不改变“Pi 批准一切动作”的安全边界。

## 7. 视觉与目标定位

```text
画面帧
  ↓
本地运动/稳定门 → 人、手、书、目标区域的低成本检测
  ↓（目标稳定且确实需要语义）
可选通用 VLM：解释画面、回答问题、讲故事
  ↓（需要“哪个目标、在哪里”）
本地候选框或未来 VLX-Seek：返回目标实例/区域
  ↓
画面坐标 → LEFT/CENTER/RIGHT 或经校准的本机注视姿态
  ↓
SafetyGate → 已验证动作片段
```

- 视觉不能每帧直接改变关节角；目标需要稳定门、置信度门和冷却门。
- 第一期只实现 `LEFT / CENTER / RIGHT` 注视扇区。物体消失、识别不确定或模型回复 `None` 时回待机/倾听，而不是盲扫。
- VLX-Seek 适合开放词汇目标定位和拒识，不是聊天、ASR 或 TTS 模型。当前公开的 10B 版要求 GPU；未来若有小模型与 RKNN/ARM 支持再评估 Orange Pi。
- 默认不进行人脸身份识别，不长期存储儿童图像；云端上传需可见、可关闭，并只发送当前必要帧。

## 8. 运动、机械与保持

- `J1`（底座偏航）受重力矩较小，直驱较合理。
- 所有水平俯仰轴都按 `力矩 = 质量 × 9.81 × 质心力臂` 计算；低速不减少静态重力矩。
- 灯头 J4/J5 可在轻量、短力臂、实际温升合格时直驱；J2/J3 应优先通过扭簧、恒力弹簧或配重抵消 70–90% 重力矩，而不是长期用电流硬扛。
- “位置到达”不等于“长期承重”。保持必须在电机持续使能、带实际负载、温升/位置误差/电源电流均通过测试的条件下启用。
- MKS 纠正电机轴的偏差，不能修复结构弯曲、轴承游隙、联轴器打滑或材料弹性变形。
- 外部参考系统的“头部角度”不能套用到本机。所有 `look_at`、`nod` 等语义只映射为本机 J1–J5 已校准的姿态和动作 ID。

## 9. 不可绕过的安全路径

```text
AI / 语音 / UI / 视觉 / 示教回放
              ↓
      统一 SafetyGate.check_and_clamp()
急停、限位、回零、校准、CAN 心跳、故障、温度、
软限位、速度、加速度、动作预算、目标可见性
              ↓
     SEQ / INT / TRJ 动作仲裁
              ↓
       已验证 MKS CAN 适配器
```

急停是硬件切断使能或电机动力；软件停止只是附加保护。CAN 断线、心跳丢失、未知固件、未回零、传感器异常、模型超时或任何未知状态，默认拒绝新的运动。

## 10. 分阶段实施

| 阶段 | 交付物 | 完成条件 |
|---|---|---|
| 0：仿真基线 | 现有单元测试、虚拟总线、轨迹与安全状态机 | 不访问真实 CAN/GPIO |
| 1：单轴硬件 | 读取状态、回零、限位、极低速位置、急停 | 单台无负载，手册/固件/方向/温升全部确认 |
| 2：五轴与动作 | 五轴 CAN、校准、动作库、示教/低速回放 | 所有入口均无法绕过 SafetyGate |
| 3：基础互动 | 麦克风、扬声器、VAD、三扇区视觉、LED、网页控制台 | 云端离线时安全功能仍可用 |
| 4：多模型对话 | `ModelRouter`、`zh/en/da` 会话、费用上限、实时音视频适配器 | 统一 schema、可替换提供商、隐私开关可用 |
| 5：按需扩展 | P4+C6 媒体前端或局域网 GPU/VLX-Seek | 仅在性能测试证明有必要后加入 |

## 11. 当前未决项

1. MKS SERVO42D CAN 的实物固件、完整手册、节点/心跳/保持/故障策略与真实帧校验。
2. 每轴的实际质量、质心、连续保持力矩、弹簧补偿、温升和结构刚度。
3. 麦克风、扬声器、功放与电源布局后的回声和噪声实测。
4. 中文、英文、丹麦语各自的 ASR、实时对话和 TTS 候选模型的真实延迟、识别率、声音质量与费用对比。
5. 是否需要 P4+C6；以 Pi 3B 实测的全双工稳定性和视频延迟决定。
6. 是否采购局域网 GPU 主机；只有需要本地高质量细粒度视觉时才评估 VLX-Seek。

## 12. 代码现状与下一次重构

现有 `lamp_core` 已有安全状态机、轨迹、`SEQ / INT / TRJ`、行为白名单、静止门、虚拟硬件、离线 Vosk 适配器和可选 OpenAI 图像理解客户端。它仍是安全仿真基线，尚未包含真实 MKS CAN 驱动、实时媒体流或多模型路由。

下一次软件重构应按以下顺序进行：

1. 建立真实 MKS 的只读状态与单轴安全适配器；
2. 让所有 UI、语音、视觉与回放都统一进入 `SafetyGate`；
3. 定义 `ModelProvider`、`ModelRouter` 和统一 `BehaviorProposal`，把当前 OpenAI 客户端变为可替换适配器；
4. 加入语言会话、费用上限和隐私状态；
5. 最后接入实时音视频提供商，且只在运动安全已经稳定后启用。
