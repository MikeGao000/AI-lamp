# MKS CAN 单轴实机动作测试

这一步只测试一个已接好、已验证 CAN 通讯的电机；它不运行五轴姿态库。

程序先读取电机的累计编码器和转速，再以该实时位置为起点，执行一个最多 4096 counts（电机轴 90°）的绝对坐标动作。这样不会假定当前零点，也不会因上次断电的位置而发送一个固定绝对坐标。

在树莓派项目根目录执行：

```bash
python3 run_mks_single_axis_motion.py --node-id 1
```

上面是 dry-run，只打印配置和帧策略，绝不打开 `can0`。确认 J1 机械结构有足够空间后，执行：

```bash
python3 run_mks_single_axis_motion.py --node-id 1 --execute
```

默认参数为 10 RPM、加速度 1、正方向 4096 counts。若要向反方向动作，用：

```bash
python3 run_mks_single_axis_motion.py --node-id 1 --delta-counts -4096 --execute
```

要做十次往返重复性测试（共 20 段动作，每一来回回到该轮开始的编码器位置附近），使用：

```bash
python3 run_mks_single_axis_motion.py --node-id 1 --delta-counts -4096 --cycles 10 --execute
```

上例适用于已在约 `+4092` counts 的 J1：先反向回到接近零位，再正向返回，重复十次。若当前想先向正方向运动，就把 `--delta-counts` 改为 `4096`。程序逐段打印 `segment N/20`、编码器目标和实际误差；一段失败便立即结束，不再启动后续段。

## 实时变速／曲线加速度测试

MKS 的 `F5` 支持运动中更新目标位置和速度。`--profile curve` 向同一个目标连续发送四个 `F5` 更新，电机不在四阶段之间等待停稳；最后一阶段以较低速度进入目标。

```bash
python3 run_mks_single_axis_motion.py --node-id 1 --delta-counts 4096 --profile curve --execute
```

装有 **13.7:1 行星减速器**时，改用输出关节角度；`90°` 自动换算为 `56115` motor counts（电机 3.425 圈），输出角度仍是 90°。该模式的变速曲线为 `12 RPM / acc 16 → 30 / 40 → 60 / 72 → 18 / 20`，最高输出速度约 `4.38 RPM`：

```bash
python3 run_mks_single_axis_motion.py --node-id 1 --gear-ratio 13.7 --joint-degrees 90 --profile curve --execute
```

若想要更快、更有动态感的 90° 输出测试，使用 `fast-curve`。它将峰值提升到电机 `120 RPM`（13.7:1 后约 `8.76 RPM` 输出），曲线为 `30 / acc 48 → 80 / 112 → 120 / 160 → 30 / 48`：

```bash
python3 run_mks_single_axis_motion.py --node-id 1 --gear-ratio 13.7 --joint-degrees 90 --profile fast-curve --execute
```

`acc` 是 MKS 的 0--255 内部加减速等级，数值越大，速度变化越快；它不是可直接换算成 `rad/s²` 的标定单位。曲线不写入电机持久参数。先运行一次曲线并观察其顺滑度、声音和位置误差；通过后再考虑将 `--profile curve` 与 `--cycles` 组合做重复性测试。

成功时会打印动作前编码器、目标编码器、动作后编码器与位置误差，并以 `PASS` 结束。验收容差是位置 ±8 counts、反馈转速 ±1 RPM，以适配 MKS 的整数编码器和 RPM 量化；例如实测 `4092 / -1 RPM` 对于目标 `4096` 是成功。若该轴已经在转、CAN 没有回应或 15 秒内未进入该容差，程序会以失败退出；此时先不要进行下一轴或五轴姿态测试。

这个探针执行后保持位置控制使已安装的轴维持姿态；它不写入电机参数、零点或动作包络。
