# 验证体系与仿真边界

更新日期：2026-08-30

机器人运动不能通过“CAN 发出位置且电机转了”验收。验证必须由低风险、可重复的层级逐步向真实机构推进；任何一层通过都不替代下一层。

## 1. 五层验证体系

| 层级 | 验证对象 | 可证明的事 | 不能证明的事 |
|---|---|---|---|
| L0：代码契约 | 纯函数、状态机、协议编解码 | 限位检查、队列优先级、故障拒动、输出 schema | 电机实际是否执行 |
| L1：理想轨迹 | 完美跟踪的数学模型 | 关节目标、时间同步、软件位置/速度包络 | 扭矩、重力、CAN、温升、碰撞 |
| L2：非理想数字孪生 | 延迟、跟随误差、摩擦、回差、重力、柔性 | 规划器对已建模扰动的鲁棒性 | 未测量的机械问题 |
| L3：硬件在环 | 单台 MKS、CAN、限位、急停、假负载 | 真实通信、反馈、故障策略、驱动器行为 | 五轴真实碰撞与载荷 |
| L4：逐级实机 | 单轴 → 两轴 → 五轴、真实灯臂 | 真实机构的安全、重复性、温升和体验 | 对未经测试新负载的保证 |

## 2. 当前 L0/L1 工具

运行全部软件契约测试：

```powershell
python -m unittest discover -s tests -v
```

运行代表性动作的理想验证：

```powershell
python simulate_ideal_verification.py
```

运行所有 32 个软件关节极限角点之间的 992 条转场：

```powershell
python simulate_ideal_verification.py --exhaustive
```

理想验证器假设零跟随误差、零 CAN 延迟、无限扭矩、无重力、无弹性变形和无碰撞。它用于证明规划代码自洽，不得用于宣称实物可安全执行。

## 3. 每层的输入与验收物

### L0：代码契约

- 为每个安全入口写单元测试：UI、语音、视觉、AI 建议、示教回放都必须经过同一 `SafetyGate`。
- 为真实 MKS 协议建立录制 CAN 帧的 golden tests：CRC、节点 ID、长度、错误回复、超时与重复帧。
- 为 `SEQ / INT / TRJ` 建立属性测试：任意 `INT` 都清空软队列；故障/急停后绝无新的运动命令。

验收物：测试报告、协议帧样本、版本锁定的驱动器手册。

### L1：理想轨迹

- 使用当前 `JointLimit` 验证每帧位置与离散速度不越界、所有关节共用时间轴并同时到达。
- 预设动作、示教回放和关节极限角点转场都要跑。
- 当前只**报告**加速度/jerk；真实数值阈值必须由机械和驱动器测试后写入配置。

验收物：每次构建的动作报告、最大速度/加速度、目标姿态快照。

### L2：非理想数字孪生（在实测参数可得后建立）

每轴至少记录：质量、质心力臂、转动惯量、摩擦、弹簧补偿曲线、回差、结构刚度、连续可用扭矩、温度模型、编码器/关节比和 CAN 往返延迟。

注入场景至少包括：

1. 单轴跟随误差与低速抖动；
2. 负载变化、水平保持和长时间温升；
3. CAN 帧延迟、丢失、乱序与节点掉线；
4. 一轴先到/一轴落后、到位阈值误判；
5. 视觉目标延迟、突然消失、置信度抖动；
6. 动作途中 `INT`、硬限位、急停与重新回零。

验收物：每个场景的可复现参数、期望状态转换、实际结果与失败日志。

### L3：硬件在环

顺序固定为“只读 → 回零 → 小角度 → 停止 → 带假负载保持”。每一步只接一台电机，且电机固定在台架上，24 V、CAN、NC 限位与物理急停均独立可测。

必须测量：CAN 命令到开始运动/到位的时间，编码器误差，驱动温度，电源电流，保持 1/5/15/30 分钟的漂移，通信中断策略，以及急停后的机械下垂距离。

### L4：逐级实机

1. J1 无负载；
2. J4/J5 与真实灯头；
3. J2/J3 加真实或等效重力负载及弹簧补偿；
4. 两轴协同；
5. 五轴低速预设动作；
6. 视觉注视；
7. 最后才允许触碰动作。

每增加一轴、一个负载或一个新动作，都重跑急停、限位、CAN 掉线、温升和回零检查。

## 4. 何时需要更强的运动控制

第一版是慢速、安全姿态与预设动作，可由 MKS 的内部位置模式执行已验证段。若测试发现以下任一情况，就必须升级为更密集的外部轨迹流/同步机制，或另设实时运动控制器：

- 五轴不能在要求的误差内同步到位；
- 连续动作出现明显顿挫、积压或跟随误差；
- 位置保持或重力补偿需要随姿态实时改变；
- 需要连续视觉跟随、接触控制或复杂避障；
- CAN 时序、驱动器队列或节点协议不能保证安全停止。

## 5. 当前结论

现有项目已完成 L0 的一部分和 L1 的理想数学检查；L2–L4 尚未完成。真实 MKS CAN 驱动未接入前，不应把任何仿真通过描述为“电机方案已经验证”。
